For our project specifically, the network module creates the VPC, public/private/database subnets, NAT, route tables and Kubernetes subnet tags. The EKS and RDS modules consume those network outputs.   HistData_Project_Chat_Handover

EKS then creates its OIDC provider, which is required by the IAM module to create IRSA trust relationships for the application, External Secrets, and AWS Load Balancer Controller.   HistData_Project_Chat_Handover

RDS depends on the database subnets and EKS-related security-group access, while Secrets Manager provides the database credentials consumed through External Secrets.   HistData_Project_Chat_Handover

I structure the Terraform dependencies from the network upward. The VPC creates public, private and database subnets. EKS runs in the private networking and creates an OIDC provider used for IRSA roles. RDS runs in isolated database subnets and allows Oracle traffic only from EKS. The application accesses S3 using IRSA and gets database credentials from Secrets Manager through External Secrets. The Load Balancer Controller creates the ALB, ACM provides TLS, and Route 53 points the application domain to the load balancer. Terraform builds most of this dependency graph automatically through module output references.
